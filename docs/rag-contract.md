# RAG Contract

The first RAG implementation uses the supplied local policy Markdown only. It does not use web search, external documents, DeepSeek, or a cloud vector database.

## Policy chunks

`PolicyDocumentLoader` creates exactly one `PolicyChunk` per `## Section N: Title` heading. Each chunk stores a stable `section_id`, the heading-derived `section_title`, the section text, the safe basename `source_file`, and a deterministic citation created at ingestion time. For the supplied fixture, the citations are:

```text
sample_policy.md — Section 1: Home Water Damage Coverage
sample_policy.md — Section 2: Personal Property Protection
```

Malformed, empty, missing, or sectionless documents produce controlled loader errors. Citation strings are never generated by an LLM.

## Local vector store

`ChromaPolicyVectorStore` is the approved local backend selected for this project. It persists under the configured `POLICY_INDEX_PATH`, stores section metadata with each vector, and exposes only `build`, `search`, and `reset_or_rebuild` behavior through the application-facing interface.

The embedding adapter is deterministic and offline. It creates normalized hashed-token vectors locally, so test runs do not download an embedding model or require a cloud account. This is still a real Chroma vector index; the deterministic embedding is an implementation detail behind the store boundary and can be replaced without changing retriever or business code.

Indexing uses stable section IDs with upsert semantics. Rebuilding deletes and recreates the configured collection before indexing, so repeated rebuilds do not duplicate documents. Runtime index artifacts under `runtime/` are ignored by Git and mounted by Compose.

## Retrieval and fallback

`PolicyRetriever.search` normalizes whitespace without changing query meaning, delegates to the vector store, and filters results below the configured `POLICY_RETRIEVAL_MIN_RELEVANCE`. It returns an explicit `found` flag and an empty chunk list when no evidence meets the threshold. `POLICY_RETRIEVAL_TOP_K` and the threshold are configurable through `Settings`, `.env.example`, and Compose. The current default threshold is `0.15` for the deterministic local embedding over this small supplied fixture.

An unsupported query such as earthquake coverage returns no accepted evidence because earthquake content is absent. The retrieval service never turns a below-threshold result into policy evidence.

## Citations

`format_citations` derives public source strings only from trusted `PolicyChunk.citation` metadata. It deduplicates while preserving retrieval order and returns an empty list without evidence. It does not include absolute paths, Chroma collection names, internal IDs beyond the trusted section metadata, or model-authored citation text.
